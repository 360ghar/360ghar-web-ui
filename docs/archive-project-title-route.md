# Archived: `/project/[title]` route (removed 2026-10-24)

`src/pages/project/[title].astro` was deleted because it collided with the new
`src/pages/project/[slug].astro`. Two dynamic routes cannot both own
`/project/{one-segment}`; Astro picked `[slug]` and warned that the collision
becomes a **hard build error** in a following major version.

The file was tracked in git, and its committed version is the pre-hold page
(`ProjectPage.astro` + `loadProject`). Its **uncommitted** working-tree version —
the one removed — is preserved verbatim below so nothing is lost.

## Why removing it lost nothing

`[slug].astro` keeps the same behaviour and adds the real project page:

- It reads the same legacy catalog (`projectBySlug` from `features/projects/catalog`).
- For any legacy catalog slug it renders `<ProjectHold />` and caches the page for
  an hour — exactly what `[title].astro` did for a known project.
- For any other slug it renders the RERA project detail, or a not-found state,
  which `[title].astro` never did.

So the hold behaviour is a strict subset of what `[slug].astro` now does.

## The removed file

```astro
---
import ProjectHold from '@/features/projects/ProjectHold.astro';
import { projectBySlug } from '@/features/projects/catalog';
import { cachePage, respond } from '@/lib/cache';

export const prerender = false;
const knownProject = Boolean(projectBySlug(Astro.params.title ?? ''));
if (knownProject) cachePage(Astro, 'hour');
else respond(Astro, 'hour', { notFound: true });
---

<ProjectHold notFound={!knownProject} />
```

## To bring it back

Do not re-add it as a sibling route. Restore the hold branch inside
`src/pages/project/[slug].astro` instead, which is where it now lives. The
`src/pages/hi/` tree is generated by `scripts/sync-hi-routes.mjs` and git-ignored,
so it follows the English tree automatically.
